# 스마트 팩토리 관제 시스템 트러블슈팅 및 디버깅 전수 기록 (Troubleshooting Log)

본 문서는 Vue 3 Composition API 기반의 스마트 팩토리 기상 재해 관제 시스템을 개발하는 과정에서 발생한 핵심 기술적 난제와 버그, 그에 대한 원인 분석 및 해결 방안을 체계적으로 정리한 엔지니어링 일지입니다.

---

## 1. 컴포넌트 조건부 렌더링(v-if) 탭 전환 시 화면 상태 유실 및 뒤로가기 오작동

### 문제 상황
* 기존 단일 컴포넌트(`WeatherParent.vue`)에서 `v-if="selectedTab === 'detail'"` 형태로 화면을 전환할 때, 브라우저 주소창(URL)이 항상 `/`에 고정되었습니다.
* 특정 산단의 위험 경보 화면을 동료 작업자에게 URL로 공유하거나 북마크할 수 없었으며, 브라우저 뒤로 가기를 누르면 직전 작업 화면이 아니라 외부 사이트로 튕겨 나가는 현상이 발생했습니다.

### 원인 분석
* 브라우저의 History API와 화면 상태가 동기화되지 않고, 메모리 상의 임시 변수(`selectedTab`)에만 의존하여 렌더링을 제어했기 때문입니다.

### 해결 방안
* **Vue Router 4 도입 및 동적 세그먼트 매핑**:
  * 메인(`/`), 상세(`/weather/:cityId`), 특보(`/alerts`), 레이더(`/radar`), 아카이브(`/archive`)로 최상위 뷰(View) 컴포넌트를 분리했습니다.
  * 검색창 입력값을 `watch(searchQuery)`를 통해 URL 쿼리스트링(`?search=`)과 실시간 동기화하여 주소 복사만으로 동일한 필터링 결과를 공유할 수 있도록 개선했습니다.

## 2. 브라우저 새로고침(F5) 시 사용자 설정값(온도 단위, 즐겨찾기) 초기화

### 문제 상황
* 작업자가 온도 단위를 화씨(℉)로 변경하거나 중요 산단을 즐겨찾기(⭐)로 등록한 뒤 페이지를 새로고침하면 기본값(℃, 초기 6대 산단)으로 초기화되었습니다.

### 원인 분석
* Pinia 스토어의 `ref` 반응형 상태는 브라우저 메모리에만 상주하므로, 페이지가 다시 로드되는 순간 초기 배열로 재할당되기 때문입니다.

### 해결 방안
* **Pinia Setup Store와 localStorage 양방향 영속화 동기화**:
  * `configStore.js`: 초기 로드 시 `localStorage.getItem('skala_temp_unit')`을 읽어오고, `watch(unit)`를 통해 변경 즉시 스토리지에 기록.
  * `weatherStore.js`: `favorites` 목록을 `watch(favorites, ..., { deep: true })`로 감시하여 실시간 로컬 스토리지 자동 저장 구현.

## 3. 다중 산단 기상 데이터 순차 호출 시 통신 병목 및 렌더링 지연

### 문제 상황
* 6대 국가산업단지의 실시간 날씨와 대기질 데이터를 불러올 때 `for` 루프 내부에서 `await fetchCurrentWeather()`를 순차 실행하여 전체 로딩 시간이 3~4초 이상 소요되었습니다.

### 원인 분석
* 자바스크립트의 싱글 스레드 이벤트 루프에서 비동기 HTTP 요청을 직렬(Waterfall)로 대기하여 네트워크 대역폭을 비효율적으로 사용했습니다.

### 해결 방안
* **`Promise.all` 기반 병렬 비동기 통신 아키텍처 구축**:
  ```javascript
  const results = await Promise.all(
    complexes.value.map(async (complex) => {
      const [weatherData, pollutionData] = await Promise.all([
        fetchCurrentWeather(complex.lat, complex.lon),
        fetchAirPollution(complex.lat, complex.lon).catch(() => null)
      ]);
      return { ...complex, ...weatherData, ...pollutionData };
    })
  );
  ```
* 전체 6대 산단 및 대기질 동시 수신 시간을 평균 0.4초 이내로 단축(70% 이상 성능 향상)했습니다.

## 4. 모든 산업 공정에 동일한 열팽창 계수 일괄 적용에 따른 도메인 왜곡

### 문제 상황
* 석유화학, 반도체, 제철 등 서로 다른 공정을 가진 산단 전체에 일률적으로 CNC 공작기계 열변형 오차($\Delta L$)를 적용하여 현장 데이터의 신뢰성이 저하되었습니다.

### 원인 분석
* 열팽창은 금속 절삭 가공에만 유효한 물리 지표이며, 석유화학은 배관 부식/낙뢰, 반도체는 클린룸 파티클, 제철은 하천 침수가 핵심 리스크 요인입니다.

### 해결 방안
* **공정별 특화 위험 지표(Custom Risk Metric) 동적 계산 엔진 분기**:
  * 창원 (정밀기계): 열변형 오차 ($\mu\text{m}$)
  * 울산/여수 (석유화학): 고습 배관 부식 위험도 (%) 및 낙뢰 송전선로 트립 취약도
  * 군산 (대형 프레스): 작동유/유압유 과열 위험 온도 (℃)
  * 광주 (반도체): 초미세먼지 유입 시 클린룸 HEPA 필터 차압 부하 ($\mu\text{g/m}^3$)
  * 포항 (제철): 집중호우 시 지하 모터실 침수 및 냉각수 부하 지수 (%)

## 5. 빌드 번들 크기 비대화 및 코드 스타일/린트 충돌

### 문제 상황
* 프로젝트 초기 모든 뷰 컴포넌트를 한 번에 번들링하여 초기 로딩 청크가 무거웠고, 소스코드 및 주석 내 중간점 문자로 인해 린트 경고 및 가독성 저하가 발생했습니다.

### 원인 분석
* 정적 임포트(`import View from '...'`) 방식과 비표준 특수문자 혼용이 원인이었습니다.

### 해결 방안
* **Vue Router 지연 로딩(Lazy Loading) 및 정적 린트 자동화**:
  * `component: () => import('@/views/WeatherRadarView.vue')` 형태로 라우트별 청크 분할 적용.
  * 저장소 내 중간점 문자를 100% 제거하고 `oxlint` 및 `eslint` 자동 검증을 통과하여 0 Errors, 0 Warnings를 달성했습니다.
